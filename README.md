# Truck Service CMS (Transportation corporation of canada Clone)

A fully custom, lightweight Content Management System (CMS) built in Core PHP using the MVC (Model-View-Controller) architecture. This application is designed to manage a trucking company's website, allowing administrators to dynamically control banners, homepage text, services, site settings (like logos and contact info), and read incoming contact messages.

---

## 📁 1. Project Architecture

The project strictly follows a custom MVC pattern without relying on any external frameworks (like Laravel or CodeIgniter). All requests run through a single entry point.

```text
/truckService
│
├── /app                  # Core application logic
│   ├── /config           # Database connection and site constants
│   ├── /controllers      # Handles HTTP requests and binds models to views
│   ├── /core             # Foundation classes: Router, Controller, Database
│   ├── /helpers          # Utility functions (CSRF, Flash Messages)
│   ├── /models           # Database logic and queries
│   └── /views            # Frontend HTML and Admin UI layouts
│
├── /public               # Publicly accessible directory (Document Root)
│   ├── /assets           # CSS, JS, and static images
│   ├── /uploads          # Dynamically uploaded user files (Banners, Logos, etc.)
│   └── index.php         # The ONLY entry point for the entire application
│
└── /database             # Contains SQL scripts used for initial setup
```

---

## ⚙️ 2. How the Application Works (Step-by-Step)

1. **The Entry Point**: Every request goes to `/public/index.php`.
2. **Security Check**: `index.php` initializes secure HTTP-only sessions, starts the CSRF token validator (to block malicious form submissions), and loads the configuration file.
3. **The Router**: `index.php` passes the URL to `app/core/Router.php`. The Router reads the URL and decides which Controller method to call (e.g., `/services` calls `HomeController::services()`).
4. **The Controller**: The chosen Controller method executes. It asks the **Model** for any necessary data.
5. **The Model**: The Model safely connects to MySQL using PDO (Prepared Statements), fetches the requested data, and returns it to the Controller as an array.
6. **The View**: The Controller injects that data into a **View** (HTML file). The View loops through the array to display the content on the screen for the user.

## 🗄️ 3. Database Structure & Data Storage

The CMS utilizes a MySQL database named `truck_service`. It contains **6 tables**:

1. **`admins`**:
   - Stores the `username` and securely hashed `password` for the admin panel.
2. **`settings`**:
   - Stores exactly **1 row** containing global site configuration: `site_name`, `phone`, `email`, `address`, social links, and the filename of the `logo`.
3. **`banners`**:
   - Stores the `title` and `image` filename for the homepage slider.
4. **`homepage_sections`**:
   - Stores dynamic sections for the homepage. Each row has a unique `section_key` (hero, about, cta, why_choose_us), a `title`, `content`, and an optional `image`.
5. **`services`**:
   - A dynamic CRUD table storing the trucking services offered. Contains `title`, `description`, and a cover `image`.
6. **`contact_messages`**:
   - Stores form submissions from the frontend Contact page. Contains `name`, `email`, `subject`, `message`, and an `is_read` boolean toggle.

### How Uploaded Data is Stored

When an admin uploads a file (Logo, Banner, or Service image):

1. The PHP backend verifies the extension (`jpg`, `png`, `webp`, `gif`).
2. The file is renamed to a 100% unique ID using time and randomness (e.g., `1778238044_69fdc25c29dd1.jpg` or `logo_177826_5f.png`).
3. The physical file is moved to `/public/uploads/`.
4. Only the **filename** (string) is saved in the MySQL database.
5. When an admin uploads a _new_ image to replace an existing one, the backend runs `unlink()` to automatically delete the old file and prevent server bloating.

## 🛡️ 4. Security Implementations

- **SQL Injection Prevention**: All queries to the database are executed using PDO Prepared Statements (`->prepare()` and `->execute()`). Variables are never concatenated directly into SQL strings.
- **XSS (Cross-Site Scripting) Protection**: All data rendered on the frontend is passed through `htmlspecialchars()` so malicious JavaScript cannot be executed.
- **CSRF (Cross-Site Request Forgery)**: Every POST request is verified against a secure Session Token generated by `Helper.php`. If a third-party site tries to submit a form to the application, it is instantly blocked.
- **Access Control**: Every admin method (`dashboard()`, `settings()`, `banners()`, etc.) runs a strict check for `$_SESSION['admin_id']`. If missing, the user is booted to the login screen.

## 🛠️ 5. How to Make Changes to the Code

### Scenario A: Modifying the Frontend UI Design

1. To change CSS styles, edit `public/assets/css/style.css`.
2. To change the overall layout structure (Navigation bar, Footer), edit `app/views/layouts/header.php` and `footer.php`.
3. To change the homepage content structure, edit `app/views/home.php`.

### Scenario B: Adding a Brand New Page (e.g., "FAQ")

To add a new page to the MVC architecture, follow these 4 specific steps:

1. **Create the View File**: Create a new file `app/views/faq.php` and include your standard header and footer:

   ```php
   <?php require_once 'layouts/header.php'; ?>
   <div style="padding: 40px; min-height: 50vh;">
       <h1>Frequently Asked Questions</h1>
       <p>Welcome to our new FAQ page. Add your content here.</p>
   </div>
   <?php require_once 'layouts/footer.php'; ?>
   ```

2. **Add a Method to the Controller**: Open `app/controllers/HomeController.php` and add a new method that calls the view you just created.

   ```php
   public function faq() {
       $this->view('faq', ['pageTitle' => 'FAQ - Trucking Service']);
   }
   ```

3. **Register the Route**: Open `app/core/Router.php` and add a new case to the switch statement.

   ```php
   case 'faq':
       $homeController->faq();
       break;
   ```

4. **Add it to the Navigation Menu**: Open `app/views/layouts/header.php` and add a new `<a>` tag inside the `<div class="nav-links">` section.
   ```php
   <a href="<?= BASE_URL; ?>/faq">FAQ</a>
   ```

Now, if you visit `localhost/truckService/faq`, the page will render and be accessible from the navigation bar!

### Scenario C: Adding a New Database Table & Admin Module

1. Create the MySQL table using a SQL script.
2. Create a Model in `/app/models/` (e.g., `FaqModel.php`) mimicking `ServiceModel.php`.
3. Add a backend controller method in `AdminController.php` to fetch the data.
4. Create an admin view in `app/views/admin/` to allow the admin to add/edit the rows.
5. Link it up in `app/views/layouts/admin_header.php` so it appears on the Admin Sidebar.

## 🚀 6. Local Setup Instructions

1. Install **XAMPP**.
2. Clone/Move this project directory into `C:\xampp\htdocs\truckService`.
3. Open **phpMyAdmin** (`http://localhost/phpmyadmin`) and create a database named `truck_service`.
4. Import the SQL structure (or run the scripts inside the `/database/` folder).
5. Ensure `app/config/config.php` has the correct `BASE_URL`:
   ```php
   define('BASE_URL', 'http://localhost/truckService');
   ```
6. Visit `http://localhost/truckService` to view the site.
7. Visit `http://localhost/truckService/login` to access the Admin Panel.
